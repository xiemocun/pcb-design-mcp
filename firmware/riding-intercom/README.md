# 骑行对讲机：首轮参考板原型固件

两台 ESP32-S3，机身扬声器，同时采集和播放，通过私有 Wi-Fi LR 链路互传语音。无需手机、SIM、路由器或互联网。固件目标为 ESP32-S3、16MB Flash、8MB Octal PSRAM，音频接口兼容 ESP32-S3-Korvo-2 V3.1。它不是已有 AM2302 主板的固件，不能刷到那块板子。

当前实现包括 ES7210 四路同步输入（双麦、模拟播放参考、空通道）、ES8311 双槽播放、ESP-SR FD 回声消除和 NSNET2 降噪、16kHz/16bit 单声道 Opus 16kbps/20ms、双方持续传输、随机启动会话、配对 WPA2/PMF、序号/时间戳检查、60ms 初始抖动缓冲、丢包补偿及断线恢复。没有按键轮流发言，也没有用 VAD 关闭另一方的语音。

源码和编译证据不能证明真实距离、音量或风噪效果。尚未烧录/上电；参考板的四路 ADC 数据顺序、AEC 双讲表现、运行内存与实时负载均需上板确认。定制小板原理图和 PCB 尚未完成，MCP 内目前保存的是核心器件和接口草案。

## 构建

本工作区已有工具链时，从仓库根目录执行：

```sh
python3 firmware/riding-intercom/build_local.py --unit a
python3 firmware/riding-intercom/build_local.py --unit b
```

构建前校验官方组件压缩包和解压内容。`prepare.py` 首次生成一组随机配对凭据，之后保持不变；两台固件必须来自同一份 `provisioned/pair.h`。该文件与已编译固件包含本机对的密钥，不应作为通用默认密钥发布。程序不打印密钥，不访问外部账户。

已固定依赖：ESP-IDF 5.5.0、esp_codec_dev 1.6.2、esp_audio_codec 2.6.2、esp-sr 2.6.1、esp-dl 3.3.14、dl_fft 0.8.0、cjson 1.7.19、esp_new_jpeg 1.0.2。注册表原包、下载地址及 SHA256 在 `work/riding-intercom/sources/manifest.json`，厂商许可证保留在各组件中。音频库包含仅限 Espressif 产品的许可证，当前目标符合该限制。

`build_local.py` 使用本工作区已有 PlatformIO 包内的 Xtensa 编译器，通过 IDF CMake/Ninja 构建；不需要本产品未使用的 RISC-V ULP 工具链，不修改其他工程。Python 构建模块来自已安装的工具包。`platformio.ini` 同样保留双机配置，但本轮验收以直接 IDF 构建为准，PlatformIO 的完整工具下载流程未完成。

标准 ESP-IDF 5.5 环境也可运行 `prepare.py` 后，用 `idf.py -B build-a -D RIDE_ROLE_AP=1 build` / `idf.py -B build-b -D RIDE_ROLE_AP=0 build` 构建；这条外部环境路径尚未单独验收，需先选定目标 esp32s3 和独立 SDKCONFIG。

## 首次上板

只在符合上述 Flash/PSRAM 和音频接线的硬件上使用。两个参考板都接各自的扬声器和稳定 5V 电源，先完成单板检查，再进行双机通信。参考板现有天线与未来 WROOM-1U 外置天线版本要分别记录结果，不能混为同一个射频样机。

1. 按构建目录 `flasher_args.json` 中的地址烧录 bootloader、分区表、应用和 `srmodels/srmodels.bin`。不能只烧应用而漏掉降噪模型。A 和 B 使用对应应用。
2. 串口 115200 查看启动记录：芯片、PSRAM、0x18/0x40 音频器件、模型加载、I2S 格式和无线角色。任何启动失败、复位或断言都保留原日志，不视为通过。
3. 检查 MCLK=4.096MHz、BCLK=1.024MHz、LRCK=16kHz；分别激励两只麦克风及 DAC 参考输入，核实日志中的 M1/M2/REF。`ride_adc_unpack()` 只恢复标准 I2S 32位槽中的16位词顺序，实际 ES7210 通道顺序仍须测量核对。
4. 两机自动直连，串口 `m` 切换本机麦克风静音，`+`/`-` 调整播放音量。初始音量45，暂限最高80；这些是驱动音量刻度，不是声压级。
5. 每10秒输出 link、发送/丢弃/接收帧数、PLC、缓冲重同步、编解码错误、采样数和剩余内部内存。每250个采样块输出三路 RMS/削顶计数。先静止双讲，再低速骑行，最后测试城市目标路线。

初始无线配置：信道6、LR模式、关闭 Wi-Fi 省电、13dBm 传导功率上限；每对随机 SSID/密钥，最多一个对端，固定私有地址192.168.77.1/2。大陆国家码设置不等于整机无线合规已经完成，天线匹配和实际 EIRP 需跟具体硬件一起核查。

## 已做与待做验证

宿主机用同一份 `transport.c` 做了 ASan/UBSan 测试，覆盖包长/版本/时间戳校验、乱序、重复、序号回绕、丢包、重启、旧会话包和收发时钟偏差；这不等于真实 Wi-Fi 或 Opus/AEC 音质测试。

固件以固定40字节 Opus 帧传输，未启用 FEC、DTX 或 VBR。若运行时编码器不产生约定帧长，将记录错误并丢弃该帧，不伪造有效音频。丢包交给解码器 PLC；连续三帧欠载后重新缓冲，较长断流输出静音。时钟偏差通过有界跳帧/重新缓冲控制，尚未做无感异步重采样，需评估长时间通话时的可闻影响。

尚未执行：目标机编解码连续运行、I2S/DMA对齐实测、CPU/内存压力、无线吞吐与时延、声学回声消除、风噪、最大无失真音量、续航、防雨、城市1公里。后续硬件验收条件见 `work/riding-intercom/原型设计.md`。无实物不阻挡软件构建，也不能作为这些实测的替代证据。
