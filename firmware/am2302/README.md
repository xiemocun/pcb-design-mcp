# ESP32 / AM2302 可观察采集程序

此程序配合独立接收、开漏发送接口：AM2302 总线经 SN74LVC1G17 送到 MCU；MCU 经 SN74LVC1G07 拉低总线。当前绑定2026-11-04的双面地铜主板`541005c8bf52487b8b7453953fbd40bd` rev0，PCB `cffb0e18da80424aacd186827f1842f8`。`hardware.json`来自现有CAD哈希、独立网表与当前接口校验，构建从中同时生成`board_pins.h`和`bench_identity.h`。旧 TXS0102 板不适用此程序。

## 行为

- GPIO26 输出 1 释放总线，输出 0 发出启动低脉冲；GPIO27 通过施密特接收器接收数据。引脚最终以生成的头文件和电路清单为准。
- 上电等待 2.5 秒；每轮开始拉低 1.1 毫秒，释放后由 ESP32 RMT 外设捕获脉冲。相邻采样至少相隔 2.5 秒。
- 检查响应前导、40 位脉冲、校验和及量程；UART0 / 115200 输出一行 JSON。错误帧不会沿用上一轮数值。
- 当前程序只实现温湿度采集与串口输出，没有开启 Wi-Fi。协议解析的主机测试和实际 ESP32 编译分别记录；均不代替实物读取。

有效帧输出形式：

```json
{"sequence":1,"uptime_ms":2507,"status":"ok","temperature_c":25.3,"humidity_rh":65.4}
```

以上是格式示例，不是本板实测数据。无响应、帧不完整、脉冲时长错误、校验错误和超量程分别报告错误原因。

## 连接与下载

这块主板的 Type-C 仅供电，下载和数据显示走 J2。需外部 **3.3V 逻辑** USB 串口适配器：

| 主板引脚 | 连接 |
| --- | --- |
| J2.1 GND | 适配器 GND |
| J2.3 ESP RXD0 | 适配器 TX |
| J2.4 ESP TXD0 | 适配器 RX |
| J2.5 EN | 手动复位，短接到 GND 后释放 |
| J2.6 IO0 | 下载时短接 GND，正常启动时释放 |
| J2.2 V3V3 | 不接适配器电源输出；主板电源模块有反灌限制 |

主板 Type-C 的 CC 检测在电源声明 1.5A/3A 时才允许主电源开启。默认电流模式下关闭是现有设计行为，不能用短接开关来绕过。

下载进入方式：IO0 接地，EN 接地后释放，保持 IO0 接地完成下载。下载后释放 IO0，再将 EN 接地后释放进入应用。UART 使用 115200、8N1。不要将 5V 逻辑串口接到 ESP32，也不要把适配器 RTS/DTR 直接连接 EN/IO0 来冒充自动复位电路。

构建使用固定的 PlatformIO 6.1.18、espressif32 6.12.0 / ESP-IDF 5.5.0；所有工具安装在工作区 `work/interface-redesign/` 下，无需全局安装。当前绑定及编译证据见MCP项目目录`work/mainboard-firmware-sync/`；旧接口、电源修订阶段的编译证据保留。

构建成功后，`.pio/build/esp32wroom/firmware-provenance.json`记录实际源码、配置、ELF、应用/启动镜像及分区表哈希。`hardware_config.verify_build`核对这些文件、两个生成头文件、应用内ELF哈希及板身份；构建后修改源码或混入旧镜像会拒绝交付。它校验软件产物一致性，不代表完成实物测试。

## 实物验收

尚无本板实物记录。后续由工程验证依次记录电源/EN 波形、下载结果、GPIO26 与传感器总线/GPIO27 的协议波形，以及连续串口输出。断开传感器应稳定报告错误，重新接入后应恢复；正负温度解码的主机测试不能冒充传感器精度验证。主电源已改为TPSM82821ASILR强制PWM方案；当前选定铜线参考模型下VDD余量约146mV，仍缺有效电容、纹波/跃变和实际温升证据，不能凭编译或DRC放行整板功能。

## 0.2.0 台架记录

启动 JSON包含电路项目/修订/PCB身份、固件ELF SHA256、ESP-IDF reset_reason、GPIO引脚。每次启动都会输出；采集、错误帧处理及GPIO功能不变。2026-11-06重新绑定并编译到上述最新候选板，沿用其已有CAD，没有重新布线。

`bench.py capture` 只接收串口与操作员阶段标记，不烧录、不拉动 RTS/DTR。先开始记录，再给主板上电。阶段为正常采集 `connected`（至少600秒）、由台架制造总线故障 `fault`（至少60秒）、撤除故障 `recovered`（至少60秒）。后两项由操作员完成物理操作后在终端输入标记，输入 `stop` 结束。每次转场允许5秒过渡；这些时间和样本数是本项目提出的台架验收要求，并非传感器厂家保证。

`bench.py analyze` 对照交付包 `bench-expected.json` 检查身份、上电原因、样本计数/时间、连续性、错误帧无旧值及恢复。`records_match_protocol` 只说明所提供记录满足协议；`evidence_origin=synthetic` 永远是合成测试。串口记录无法证明供电波形或测量精度。包内《台架验收步骤.md》规定单独的电源和仪器检查。
