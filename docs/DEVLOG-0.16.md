## 0.16.1：原型文件闭环与实现职责

在 v16 原目录增量修改，没有建立 v17 快照，也没有改动历史项目。当前版本由 `src/pcb_mcp/__init__.py` 的 `__version__` 定义，`pyproject.toml` 和 capabilities 共用该版本。

制造审阅现在显式采用 `prototype_files_only`：它要求当前真实库、完整来源 BOM、无矛盾的声明直流预算、当前独立网表/ERC、实际 PCB 焊盘网络、布局、DRC、预览。设置铜线规则后，必须覆盖所有电源/地并运行当前实际铜线检查；线宽、支路隔离或声明载流参考错误会阻断。全网线段求和的保守压降警告保持为未解决事项，绝不改写为实际路径压降已通过。没有铜线规则时会明确产生 `COPPER_POLICY_UNDECLARED` 警告。申请必须提供 `qualification_declaration`，全部警告、原始诊断和申请声明绑定进不可变审阅，Gerber/钻孔仍须独立真人签字。

`power_integrity_check` 仍诚实返回原始未验证事项。只在几何构建和原型文件审阅中，对 `prototype_policy.UNQUALIFIED_POWER` 中明确列出的物理未知事项产生带原始严重度的审阅警告。新出现的错误、已知供电范围冲突、容量不足和证据变化仍会阻断；这些检查从未宣称完整生产资格。

ESP32 参考布局以必需器件/角色为下界，不再限定总数必须为 16/21/22/32。额外已绑定器件由 KiCad 适配器依据实际外形/焊盘边界、板框和天线禁布区安排位置，并重新核验实际网络和 DRC。歧义核心角色或实际空间不足会明确失败。项目上限为 128 元件，不能理解为任意 128 元件都一定能排下或布通。
